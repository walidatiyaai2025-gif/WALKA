## CMS-044 — maintenance and customer notices

- Reserved typed key/type `app.maintenance_notice`.
- Safe fields only: enabled, severity, bounded headline/body, optional UTC start/end.
- No URL, HTML, JavaScript, Product Master, commerce destination or executable action authoring.
- Typed Admin draft/publish/history/restore workspace.
- Published-only API `/api/v1/content/maintenance-notice` with schema/revision/ETag and server active-state evaluation.
- Flutter contract: remote -> revision-aware LKG -> bundled disabled fallback and compiled shell presentation.

## CMS-045 — safe App Config

- Reserved typed key/type `app.config`.
- Compiled flag IDs only: `show_operational_notice`, `show_account_service_note`.
- Owner-only App Config capability boundary already established by CMS-004 permissions.
- Unknown flags fail closed; no arbitrary names, secrets, auth/security policy, Product Master, ASIN/Pantone, URLs or commerce control.
- Published-only `/api/v1/content/app-config` plus Flutter remote -> revision-aware LKG -> bundled defaults.
- `show_operational_notice` gates the compiled shell notice slot; `show_account_service_note` gates a compiled static Account service note. Remote config supplies booleans only, never widgets/copy/actions.

## CMS-050 — scheduled publish/unpublish

- Additive UTC schedule metadata on existing `content_entries`; no parallel content authority.
- Schedule writes are optimistic-revision protected and recorded in immutable `content_revisions`.
- Due execution is idempotent and fail-closed when the draft revision moved after scheduling.
- `walka:content-schedule-run` is registered every minute with overlap protection.
- Public APIs continue exposing only the currently effective published snapshot; future schedules/drafts remain private.
- Production deployment prerequisite: the host must run Laravel's scheduler (for example a cPanel cron invoking `php artisan schedule:run` every minute). Registering the application schedule alone does not create a host-level cron process.

## CMS-051 — rich diff before publish

- Read-only deterministic recursive diff between current draft and live or selected historical revision.
- Added/removed/changed states with stable path ordering.
- Sensitive/admin-only key patterns are excluded.
- Values are rendered as inert text; viewing a diff cannot mutate content or history.
- Existing explicit publish capability remains the only manual publication action.
