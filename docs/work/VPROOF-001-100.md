# VPROOF-001..100 — Direct visual-proof diagnostics

Parent: #310  
Visual-release blocker: #230

## Purpose

Prevent mechanically valid PNGs from being treated as visually safe when direct proof exposes obvious alpha-edge white halo or known background contamination. Automated diagnostics are **not** owner visual acceptance and cannot mark final visual fidelity PASS.

## Implemented task waves

- VPROOF-001..010 — deterministic visible-edge ring extraction.
- VPROOF-011..020 — partial-alpha versus opaque-edge classification.
- VPROOF-021..030 — conservative near-white fringe diagnostics with explicit White-subject exception.
- VPROOF-031..040 — White/Ivory/WALKA Navy compositing metrics.
- VPROOF-041..050 — deterministic 96/160/240/384 downscale halo-bin diagnostics.
- VPROOF-051..060 — evidence-backed rejected-binary ledger and proof metadata.
- VPROOF-061..070 — fail-closed admission decisions: rejected/obvious-halo media blocks only if marked ADMITTED; quarantined states remain warnings.
- VPROOF-071..080 — machine-readable CLI/report contract with atomic JSON write and enforce mode.
- VPROOF-081..090 — dedicated CI workflow, protected-master guard, regression run, enforcement, summary and report artifact.
- VPROOF-091..100 — synthetic halo/clean/White-subject regressions, current-repository integration test and exact 100-ID coverage.

## Safety invariants

- `Images/` is read-only.
- No recoloring, geometry reconstruction, accessory invention or generative fill.
- A known rejected binary can never be accepted merely because it passes PNG mechanics.
- Automated metrics may reject obvious contamination but may never approve full visual fidelity.
- Owner visual acceptance remains required.
- Gray remains source-blocked unless the source/owner decision changes.
- Stable publication remains fail-closed until genuine 5/5 plus owner acceptance.
