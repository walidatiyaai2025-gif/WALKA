# CMS-001 — Generic content revision foundation

Tracking: #284 (parent #278)
Branch: `agent/cms-001-content-revisions`

## Goal

Provide the persistence/service foundation required for backend-first mobile content without exposing any new draft/admin data to the public API yet.

## Delivered contract

- `content_entries` owns one stable `content_key` and immutable `content_type`.
- `draft_payload` is always explicit JSON-array data; an empty array is valid content.
- `published_payload = null` means the entry has never been published.
- every effective mutation increments the entry revision exactly once.
- every effective mutation writes an immutable `content_revisions` snapshot.
- writes require the caller's expected revision and fail closed on stale concurrency.
- publish snapshots the current draft while preserving draft/history state.
- restore copies a prior immutable snapshot into a **new draft revision**; it never silently rewrites history and never auto-publishes.
- identical save/publish operations are no-ops and do not manufacture audit revisions.
- content payloads are deterministically normalized and capped at 64 KiB encoded JSON.
- actor identity is stored only as a 64-character SHA-256 fingerprint contract; raw credentials are not accepted by this service.

## Actions recorded in history

- `draft_created`
- `draft_updated`
- `published`
- `draft_restored`

`source_revision` links publish/restore events back to the snapshot they came from.

## Boundaries

CMS-001 does **not** add public routes, dashboard forms, Home/PDP wiring, media upload, arbitrary HTML/JavaScript, or changes to Product Master/ASIN/Pantone/Amazon purchase architecture.

CMS-002 will build preview/publish/rollback dashboard controls on these primitives. CMS-003 will add the public versioned content envelope and Flutter last-known-good/fallback consumption contract.

## Validation

Focused backend coverage includes:

- first draft creation
- draft update/history preservation
- stale revision conflict
- publish snapshot
- idempotent no-op saves/publishes
- restore-to-new-draft behavior
- explicit empty-vs-unpublished semantics
- immutable content type
- payload size bound
