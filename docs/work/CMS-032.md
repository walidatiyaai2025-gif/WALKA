# CMS-032 — Governed product and variant gallery assignment

Issue: #329  
Parent roadmap: #278  
Independent visual-release blocker: #230

## Scope implemented

CMS-032 adds a durable backend gallery layer on top of CMS-030 media storage and CMS-031 upload quarantine.

- `media_galleries` stores exactly one governed target reference per service-created gallery: either a stable `products.id` or `product_variants.id`, plus an optimistic revision and actor fingerprints.
- `media_gallery_items` stores deterministic zero-based positions with database uniqueness for position and media asset per gallery.
- `MediaGalleryService` performs validation before mutation and replaces/reorders gallery contents inside a database transaction.
- Only `product`-purpose `ADMITTED` media with a canonical derivative is assignable.
- Draft, archived, wrong-purpose, missing, duplicate and canonical-less media fail closed.
- Gallery size is bounded to eight items and positions must be unique and contiguous.
- Stale `expected_revision` requests fail without changing the existing gallery.
- `/admin/media/galleries` exposes product-level and variant-level editors using only eligible admitted media.
- Variant galleries are independent from product galleries. A product gallery is used only when a variant has no explicit assigned items.
- Public metadata endpoints expose stable IDs, semantic labels, position and canonical MIME/bytes/dimensions/SHA-256 only. Private source/derivative disk and storage paths are never returned.
- If assigned media is later archived, public delivery filters it. An explicit variant gallery does not silently fall back over invalid archived assignments.

## Public endpoints

- `GET /api/v1/media/galleries/products/{product}`
- `GET /api/v1/media/galleries/variants/{variant}`

Payload schema version: `1`.

## Guardrails preserved

- No media upload or binary processing change; CMS-031 remains the upload/quarantine authority.
- No automatic media admission.
- No protected `Images/` changes.
- No `mobile/assets/products/**` changes.
- No Product Master identity, ASIN, Pantone, price, rating or Amazon destination mutation.
- No Home/category/editorial assignment; reserved for CMS-033.
- No public binary delivery or Flutter remote binary cache; reserved for CMS-035.
- No claim that #230 is complete. Visual fidelity and owner-visible release acceptance remain independent gates.

## Regression coverage

`MediaGalleryGovernanceTest` covers:

- admin authentication protection;
- atomic ordered product assignment;
- optimistic revision / stale-write rejection;
- Draft, wrong-purpose and missing-canonical rejection;
- duplicate media, duplicate positions, gaps and max-size rejection;
- deterministic product fallback for variants without explicit assignments;
- explicit variant override;
- archive invalidation without unsafe fallback;
- public payload storage-path allowlisting;
- admin route reorder and stale-request preservation.
