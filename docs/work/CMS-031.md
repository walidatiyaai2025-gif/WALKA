## Runtime scope

- Protected Admin-only `/admin/media` workspace and upload action.
- PNG/JPEG/WebP raster source validation from server-read bytes.
- Client filename extension must agree with detected MIME; SVG and unsupported formats fail closed.
- Animated PNG/WebP sources are rejected.
- Limits: 16 MiB source bytes, 64–8192 px per dimension, 40 MP maximum pixel count.
- Dimensions and MIME are derived server-side; SHA-256 is computed server-side.
- Duplicate source SHA-256 is rejected before a second source truth can be registered.
- Valid source bytes are written only to the private `media_quarantine` disk using ULID/hash-derived paths.
- Quarantine disk/path is persisted on the CMS-030 `media_assets` source record.
- Successful upload remains `draft`; upload does not generate a canonical derivative, admit media, publish a URL, modify `Images/`, or modify `mobile/assets/products/**`.
- Filesystem write failure rolls back the database transaction; stored-file cleanup is attempted for any post-write failure.

## Safety boundaries

- Product Master, stable product/variant IDs, ASINs and Pantones are unchanged.
- No synthetic/recolored Gray source is created.
- No public media delivery, product/gallery assignment or mobile resolver change is included in this slice.
- Amazon handoff remains unchanged.

## Validation coverage

Focused backend tests cover:

- dashboard authentication;
- valid PNG quarantine + server-derived metadata + Draft lifecycle;
- filename/MIME spoof rejection;
- unsupported SVG rejection;
- minimum/maximum dimension validation;
- animated PNG rejection;
- source byte-size ceiling;
- duplicate SHA-256 rejection without a duplicate quarantined file;
- quarantine storage failure rolling back the media source record.

## Deployment note

The application accepts sources up to 16 MiB. Production PHP/cPanel `upload_max_filesize` and `post_max_size` must be configured at or above that application limit (with request overhead) before operators can use the full allowed size.
