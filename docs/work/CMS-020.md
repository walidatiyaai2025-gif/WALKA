# CMS-020 — Typed Home Hero editor

Tracking: #292 (parent #278)
Branch: `agent/cms-020-home-hero-editor`

## Goal

Make the first backend-controlled mobile surface owner-friendly: Home Hero copy can be edited without raw JSON while retaining the CMS-001/002 revision, preview, publish and rollback model and the CMS-003 public/mobile delivery contract.

## Typed fields

- eyebrow (max 120)
- hero title (max 160)
- supporting body (max 500)
- primary CTA label (max 64)
- search CTA label (max 64)

Button behavior stays executable Flutter logic. No URL/native behavior is remotely injectable.

## First-use behavior

Opening `/admin/content/home/hero` creates the first **private draft** only when `home.hero` does not exist. The safe initial payload matches Flutter's bundled Home Hero fallback exactly. It is never auto-published.

## Safety improvements

`HomeHeroContentDefinition` is the single backend definition for stable key/type, schema version, safe defaults, validation limits and public-field allowlisting.

The public `/api/v1/content/home` endpoint now constructs its payload from that exact allowlist. Unknown keys stored through the generic CMS editor are discarded instead of being reflected to public clients. This prevents accidental leakage of unrelated/private generic fields through a typed public content endpoint.

## Owner workflow

1. Open Content -> Home Hero.
2. Edit typed fields.
3. Save private draft.
4. Review the Home-style preview and Draft vs Live comparison.
5. Publish explicitly.
6. Restore a historical snapshot into a new draft when needed, then review/publish again.

## Validation

Feature tests cover authentication, first-use bootstrap, safe default parity, typed save, public publish propagation, field limits, stale-session conflict, restore without auto-publish and public allowlist stripping of unknown generic keys.
