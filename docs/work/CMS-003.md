# CMS-003 — Public content API + Flutter last-known-good fallback

Tracking: #289 (parent #278)
Branch: `agent/cms-003-public-content`

## Goal

Prove the first complete backend-first mobile content path with one safe typed surface: `home.hero`.

```text
/admin/content draft -> preview -> publish
        |
        v
content_entries.published_payload
        |
        v
GET /api/v1/content/home
        |
        v
Flutter remote -> last-known-good cache -> bundled fallback
        |
        v
WALKA Home hero copy + CTA labels
```

## Public delivery contract

`GET /api/v1/content/home` is an explicit allowlisted route. Generic CMS keys are not automatically public.

A valid published response contains only:

- stable key/type: `home.hero`
- `schema_version: 1`
- published revision
- published timestamp
- validated public payload
- API v1 metadata

Draft payloads, history, actor fingerprints and admin metadata are never returned.

The Home payload requires these bounded strings:

- `eyebrow`
- `title`
- `body`
- `shop_label`
- `search_label`

Unknown/unpublished content returns `404 content_not_published`. A published snapshot that fails the typed delivery contract fails closed with `503 content_invalid` instead of reaching mobile clients. Responses carry revision-based ETag and conservative public cache metadata.

## Flutter resilience contract

Flutter resolves Home hero content in this order:

1. validated remote published snapshot;
2. validated last-known-good SharedPreferences cache;
3. bundled current WALKA hero copy.

A malformed/incompatible remote response cannot overwrite last-known-good content. A remote revision older than the cached revision is rejected. The same revision with divergent payload is rejected as an immutability violation. Valid newer remote content is usable even if cache persistence itself fails.

## Initial live-controlled fields

- Home hero eyebrow
- Home hero title
- Home hero body
- primary CTA label
- search CTA label

The navigation callbacks remain executable Flutter behavior and are not remotely injectable.

## Boundaries

- no arbitrary dynamic widgets/layout execution
- no HTML/JavaScript
- no media upload yet
- no Product Master facts/ASIN/Pantone changes
- no secrets/security settings in public content
- no change to Amazon redirect purchase architecture

Later CMS slices add typed Home sections, PDP content, media, Categories/Search and information/support surfaces on top of the same revision/delivery pattern.
