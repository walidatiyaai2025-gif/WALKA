## Scope completed in this stack

### CMS-060 — governed Amazon destination authoring

- Canonical `commerce.map` content contract keyed by stable Variant ID + RegionMarket.
- Amazon destination URLs are generated from an allowlisted market host and validated ASIN; arbitrary destination URLs are not trusted.
- A dedicated owner-facing **Amazon Destinations** editor is exposed from Mobile Content. Variant IDs, Product Master ASIN/Pantone identity and canonical Amazon URLs are read-only/server-derived; the owner may only enable approved markets.
- The canonical Product Master ASIN is rechecked at every governed save/publish/restore/public boundary. A valid-looking but mismatched ASIN fails closed rather than becoming a destination.
- Every released ProductVariant must have one active US mapping because US is the deterministic client fallback. Missing/inactive released variants fail closed; unknown/duplicate mappings remain rejected.
- Admin draft/save/publish uses the existing revisioned content workflow with optimistic concurrency and immutable history.
- `variant_revision` binds mappings to the current canonical catalog revision and fails closed when stale.

### CMS-061 — verification, audit and rollback

- Published CommerceMap emits a revision-bound SHA-256 verification envelope.
- Public resolution fails closed for stale, malformed, inactive or unmapped destinations.
- Historical restore re-runs current catalog ID/ASIN/revision governance and creates a new private draft rather than rewriting history.
- Typed CommerceMap rollback requires a bounded owner reason and never republishes automatically.
- Scheduled publishing revalidates governed content before the publish transition.

### CMS-062 — Flutter dynamic Amazon destination consumption

- Added backward-compatible `/api/v1/commerce/amazon` consumption.
- Flutter parser validates schema, verification metadata, stable Variant ID, protected ASIN identity and canonical Amazon HTTPS destination shape.
- Revision-aware last-known-good cache rejects lower revisions and same-revision digest conflicts.
- Runtime registry applies dynamic mapping to destination only; protected Variant ID/ASIN and `amazon_redirect` architecture remain compiled Product Master truth.
- Failed/missing remote commerce falls back deterministically to the protected bundled Product Master Amazon destination.
- Purchase launch guard rejects non-Amazon and ASIN-mismatched candidates before handing off to `url_launcher`.

### CMS-063 — closure regression gate

- End-to-end backend regression covers typed Admin bootstrap -> governance -> publish -> public verified CommerceMap -> deterministic resolver.
- Focused regressions cover canonical ASIN tamper rejection, incomplete/inactive released-variant mapping rejection, hostile Admin identity/destination fields, market enablement, explicit publish and reasoned restore-to-private-draft behavior.
- Public commerce index participates in ETag/Cache-Control/304 delivery metadata.
- Production smoke matrix checks the commerce route, verification contract, Flutter endpoint/parser contract and runtime purchase guard.
- Existing metadata backup automatically carries CommerceMap through generic content-entry/content-revision sections and is self-validated.
- Regression asserts Product Variant ID, ASIN, Pantone and revision remain unchanged throughout the CommerceMap workflow and confirms `amazon_redirect` stays active.
